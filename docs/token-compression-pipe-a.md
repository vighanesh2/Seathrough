The five examples to lock

4. Follow-up that changes scope — new tight ask

5. Whole course / blob — ask, do not invent

No survey title. No compression

## One-canvas scope gate

Every model-generated Pipe A result is checked before it reaches the UI or Pipe B.

- A `run` must name one mechanism, bounded comparison, or worked example that fits
  on one still board.
- Every `ask` option must independently pass that same rule.
- Academic fields, course/module labels, and bundles of sibling mechanisms are
  repaired into 2–4 concrete choices.
- Selecting a choice must not immediately require another “which part?” question.
- A submitted `confirmedTightAsk` is checked again server-side; client text cannot
  bypass the one-canvas gate.

This is a semantic gate across subjects, not a topic lookup table. Phrase checks
remain as deterministic backup for obvious survey labels.
